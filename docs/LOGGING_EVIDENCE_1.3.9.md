# 1.3.9 日志证据补齐

2026-11-14（Asia/Taipei）。在第一步轻量日志基础上，补齐事件语义和命令拒绝详情。仍使用原日志、消息链、最近一轮诊断镜像与“导出诊断”，没有新增运行文件、依赖、权限、定时采样或恢复入口。

## 事件的含义

| 事件码 | 原有证据与边界 |
|---|---|
| `directory-scan-started` | 已进入本课完整目录核对。失败时没有对应完成事件。扫描阶段资源身份留空。 |
| `directory-scan-completed` | 原目录稳定与完整性检查通过；新目录沿用原检查点保存，复用目录沿用原稳定核对。附原有资源统计，不代表资源完成。 |
| `resource-opened` | 原执行器已打开并保存对应资源断点；不代表已播放。 |
| `media-playing` | 原播放循环已满足原有“非暂停且位置大于零”的记录条件；不额外引入连续推进判定。 |
| `playback-target-reached` | 原逻辑已达到用户百分比目标，或已自然结束；不是平台完成确认。 |
| `resource-confirmed` | 原逻辑已有页面标记或有效平台进度证据；保留原批量页面提示，批量检查点仅记录新增确认数量，不逐项刷屏。 |
| `document-visited` | 保留原事件，仅表示访问。重复访问不重复记此事件，不能替代`confirmed`。 |
| `task-paused` | 原暂停流程。 |
| `task-blocked` | 原人工处理流程；命令拒绝使用下面的更具体事件码。 |
| `command-rejected` | 原命令拒绝引起人工停止，附命令及已有校验详情。正常`TASK_CANCELLED`不使用此码。 |
| `recovery-started` | 原恢复逻辑已进入尝试；不是恢复成功。 |
| `recovery-verified` | 原逻辑已有持续播放、自然结束且平台确认，或继续播放并收到成功上报等证据。以原分支条件为准，未放宽条件。 |

同一流程原来已有的前端、后台提示继续保留，不能按事件条数统计完成资源数。完成数量仍以任务记录和平台证据为准。普通界面消息保持兼容默认码。

旧记录继续可读，不倒推或补造过去缺少的详情；新事件才带本轮补充字段。

原`course-refresh`、`reload-course`、`document-visited`及诊断现场的命令名保持不变，避免影响既有优先保存与重置机制。

## 身份拒绝详情

原“课程身份已改变”拒绝条件、错误文字、错误分类与控制结果均保留。在五处原失败分支增加`errorDetails`，通过原消息响应进入页面`Error.details`，再进入原人工停止现场与导出：

```json
{
  "action": "directory-checkpoint",
  "rule": "course-identity-match",
  "expectedCourseKey": "course-A::class-1",
  "actualCourseKey": "course-B::class-1",
  "actualSource": "sender.url",
  "actualRoute": "learn"
}
```

五处为资源记录、目录检查点、资源检查点、批量完成、课程结果。资源记录、目录与资源检查点、课程结果的原发送文档身份检查注明`sender.url`；批量完成原先已读取的标签检查注明`tab.url`。批量外层通过、内部资源记录拒绝时，仍如实注明内部使用的`sender.url`。没有增加实时标签读取，也不替换原校验来源。

身份无法解析时使用`null`并标记`incomplete: true`。截断或格式无效的已知证据字段同样标记不完整。`action`、`rule`、通信错误代码和事件码分开保存；时间、运行、代数与资源身份沿用原上下文。

新增`evidence`与`details`只接受有限的扁平白名单：命令、规则、预期/实际身份、来源、路由类型、恢复类型，以及已有的数量、目标、位置、时长、尝试次数和推进区间。字符串每字段最多240字符，数字必须有限；不接收任意嵌套对象。过滤常见令牌和Bearer凭证，完整网址替换为`[url omitted]`。后台和本页待保存日志均执行相同边界。

## 保留范围与限制

文档识别、任务纳入、完成条件、短时优先、音视频执行、百分比设置与切换、暂停及恢复额度、外层选择逻辑均未修改。日志不作为执行检查点或恢复权限。

详情能说明“哪个命令因什么校验被拒绝”，不保证单靠日志就能解释身份为何变化或平台为何报错。缺证据时结论为“原因未确认”，不能直接归因服务器。

日志仍最多300条、界面80条、最近观察12条、只保留最近一轮镜像。原诊断现场20 KB上限和普通保存节流继续适用；未提交即崩溃、裁剪或存储失败仍可能缺失现场。

本轮基线、增量补丁、测试及真实页验收记录集中在`artifacts/logging-evidence-20261114/`；通过与待验范围以该目录的`review.md`和`verification.json`为准。
