# 双模式使用与运行机制

当前最新版本为 **1.0.0**。外围负责选课、调度和监督；单课逻辑负责目录扫描、音视频播放、文档访问与课末核对。

## 使用

先获取课程列表。默认半自动：选一门“开始学习”，扫描目录、播放音视频、访问文档并在课末核对；结束后等待下一次选择。

点击“全自动开始”授权本轮连续选课。列表五分钟内可复用；陈旧列表和新一轮通过原列表入口更新。本轮开始后固定范围、顺序和课程名称身份；学习页仍须原课程与教学班校验。列表运行时禁止替换本轮范围。

首页进度能够可靠确认为100%才跳过，其余进入单课 learn 流程。完整目录已确认本课可处理任务完成后，即使平台总进度不足100%也结束本课。明确只有作业、考试或非任务参考资料时显示“略过：无可处理任务”。未知数量继续显示待扫描，未知资格文档不会自动排除，空白目录不作无任务结论。

明确课末失败或非网络局部恢复耗尽后，先等原执行器退出且媒体已暂停，再保存本课唯一一次外围重进额度，实际返回课表、重新唯一定位课程。第二次失败保留待处理，安全进入下一门；本轮结束不补跑。已失去页面身份、网络全局故障、验证码、关键存储错误和停止未确认时整体暂停。

“暂停”同时阻止后续选课和内层执行。“继续全自动”保留本轮结果、尝试和重进次数，接回原尝试。“切换半自动”先调用原停止入口，再撤销后续队列授权。手动刷新、扩展更新或浏览器重启、休眠后等待明确继续。后台 worker 正常休眠后重新实例化，沿用会话中的身份与监督证据，不撤销本轮授权或重置预算。

## 结果与监督边界

`job.outer` 保存本轮 ID、固定范围、每课结果、重进次数、待消费派发令牌、待确认停止令牌和阶段时间。`candidate.latestResult` 与对应 `logs[].result` 来自同一个校验后结果，代码为 `directory-scanned`、`course-completed`、`course-no-tasks`、`course-failed`。`pending` 保留内层执行待处理数，`platformPending` 单独统计目录及记录仍未确认的任务，两者不混用；未知失败数量为 `null`。普通日志不作为执行依据。

外围派发、返回、打开、停止确认阶段默认180秒；同阶段普通重试和消息不续期。暂停期间时间冻结；超时后的明确继续可重新授权一次监督核对预算，仍不重置任何重进额度。正常学习没有整课时长限制，以原播放位置、资源状态及有限恢复/末轮检查点核对执行进展；目录与首页分页扫描已经由内层接回后不设180秒整段上限；现有 get 只读附带执行器状态、展开章节/条目数或已读取页数/课程数，以变化核对进展。重复 get 和日志不算进展；缺少证据、停止或冻结时有界暂停，等待确认。监督证据单独保存在会话存储，普通 worker 重建不会刷新预算。

检查复用现有 `syncSharedJob`、后台串行处理和 `chrome.alarms`。一个外围截止时间闹钟在所有页面停止轮询时撤销后续权限；它不采样、点击、刷新或操作资源。身份/停止不确定时只暂停，不强行换课。安全留在已核实课表、无待接回学习页的二次重进导航失败，收到执行器停止确认后可保留失败并继续。

结束或切回半自动后，历史轮次记录单独折叠展示。后续单课扫描、播放、暂停和失败按当前状态显示；开始新单课时仅将旧轮标为历史，不删除结果。

## 日志

UI80条、任务随身300条保持。原诊断键兼容迁移为：普通历史最多1000条且1MiB，故障最多10组且每组20KiB，当前和最近两轮摘要，整个诊断对象最多2MiB；容量按 UTF-8 JSON 字节计算。诊断裁剪不会修改执行结果或重进额度。

普通日志沿用10秒合并；故障、停止结果、重进额度和课末优先保存。重复错误按轮次、课程、阶段和尝试聚合。导出只读，包含保留历史、故障、摘要及裁剪计数；可选诊断保存失败仅提示降级。

根站点“重新加载课程”自身导航期间，已记录的离开文档继续发出的 hello 只等待接回，不误报用户刷新；真正的新实例刷新仍需明确继续。

## 检查与限制

- `npm run check`、`git diff --check`。
- `node --test --test-concurrency=4 tests/outer-*.test.cjs`：真实前后台模块配合模拟页面验证串行派发、响应丢失、重进、取消、重启、时间预算、UI和日志容量。
- `node --test --test-concurrency=4 tests/*.test.cjs`：全量回归测试。
- 实际验证范围见 [验证说明](VERIFICATION.md)，浏览器原始诊断仅在本地保存。

已知边界：课表只有名称作为可见身份，同名、移页后定位失败或教学班变化时停止，不能猜测课程。空列表缺少可信“无课程”证据时不报全轮完成。未确认停止、全局网络故障、异常扫描错误仍可能要求人工继续。浏览器弹窗拦截、不同课程样本、磁盘延迟和长期休眠行为仍需在真实环境中验证；隔离测试不代表真实验收。


## 原页继续与运行时防休眠

- 设置 → 后台运行 → 运行时防止自动休眠：新安装默认关闭。开启后仅在任务运行或外围交接时请求 `chrome.power.requestKeepAwake('system')`，允许屏幕熄灭；暂停、结束、重置、任务状态读写失败时释放。关闭开关立即释放。使用浏览器 `power` 权限。
- 开关表示请求防止闲置系统休眠，不代表绕过合盖、主动睡眠、浏览器冻结/丢弃或系统限制。中断后仍由用户手动继续，绝不因唤醒自动重新授权。
- 课表页“继续运行”会核对原学习标签页的课程、文档、任务轮次、执行代次与停止状态，再复用原有继续入口；原页重新识别目录，保留已有记录与预算。原学习页仍存在时沿用原页；页面关闭后的接续见下节。身份不符、登录限制、执行器未停止或无响应时保留记录并提示。
- 监督间隔超过60秒仍保守暂停，新增 `outer-supervision-gap` 及 `elapsedMs` 证据，不把单次位置变化或普通轮询当成持续运行证据。正常后台同步和实际执行进度仍按原逻辑监督，不因页面不可见直接暂停。
- 恢复拒绝使用 `outer-resume-rejected` 记录，跨页确认成功记录 `outer-resume-owner`。界面标题独占一行，“继续运行”和“切换半自动”放在独立两列网格。
- 防休眠和跨页继续不改变单课资源分类、完成条件、80–100%目标、短时长排序、资源恢复或最终核对规则。


## 从课表找回上次课程

- 暂停轮次可从新打开的课表点击“继续运行”，显示上次课程名称；不要求使用原来的课表标签页。唤醒、刷新或打开课表不自动继续。
- 原学习页存在时仍核对停止状态并原页继续；原页关闭或已离开课程时，撤销旧执行身份，在当前课表标签页打开已保存且校验过的课程/资源入口。
- 保存入口无效或跳回课表时复用原课程卡片定位和打开流程；不替换课程列表，进入后以课程 ID 和教学班再次核对。课表名称不唯一、移页或课程消失时保留断点并提示。
- 页面到达后恢复原 operation/targetPurpose，再交给原内层核对目录。保留 runId、outer.id/cursor、资源记录/检查点、重进和资源恢复预算、目标百分比。已结算结果从课表继续停止确认和调度，不重开已完成课程。
- 单次找回入口限45秒，超时/暂停取消找回，保留为原课程待继续；不自动循环刷新。原页面还在但无响应时仍要求确认，不能冒险启动两份。
- 事件复用现有有界日志：outer-resume-reopen / outer-resume-page-observed / outer-resume-card-fallback / outer-resume-arrived / outer-resume-entry-timeout / outer-resume-queue。到达事件不代表播放成功。
- 真实浏览器验证的成功与失败记录见 [验证说明](VERIFICATION.md)，不能把入口到达日志当作播放成功。
