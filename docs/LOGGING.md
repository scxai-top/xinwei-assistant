# 日志与诊断

日志用于保留任务经过和故障证据。课程结果由经过校验的单课结果决定，普通日志不作为任务检查点或恢复授权。

## 保存范围

| 内容 | 上限 |
|---|---|
| 界面日志 | 80条 |
| 任务随身日志 | 300条 |
| 普通诊断历史 | 1000条且不超过1MiB |
| 故障现场 | 10组，每组不超过20KiB |
| 轮次摘要 | 当前和最近两轮 |
| 诊断对象整体 | 2MiB |

容量按UTF-8 JSON字节计算。普通日志按10秒窗口合并，故障、停止结果、重进次数和课末信息优先保存。重复错误按轮次、课程、阶段和尝试聚合；裁剪日志不会修改执行结果或恢复次数。

## 主要事件

| 事件码 | 含义与限制 |
|---|---|
| `directory-scan-started` | 开始核对本课完整目录。 |
| `directory-scan-completed` | 目录稳定与完整性检查通过，不代表资源已完成。 |
| `resource-opened` | 已打开资源并保存断点，不代表已经播放。 |
| `media-playing` | 播放循环观察到未暂停且位置大于零，不额外保证跨时点连续推进。 |
| `playback-target-reached` | 达到用户设置的播放目标或自然结束，不等于平台确认完成。 |
| `resource-confirmed` | 已有页面完成标记或有效平台进度证据。 |
| `document-visited` | 已访问文档，不能代替平台完成确认。 |
| `task-paused` / `task-blocked` | 任务暂停或需要人工处理。 |
| `command-rejected` | 命令因校验失败被拒绝，附命令及已有校验详情；正常取消不使用此码。 |
| `recovery-started` | 已开始恢复尝试，不代表恢复成功。 |
| `recovery-verified` | 当前恢复分支已有持续播放、平台确认或成功上报等相应证据。 |
| `outer-resume-reopen` / `outer-resume-page-observed` | 开始找回课程或观察到页面响应。 |
| `outer-resume-card-fallback` / `outer-resume-arrived` | 改用课程卡片入口或确认到达课程，不代表播放成功。 |
| `outer-resume-entry-timeout` / `outer-resume-queue` | 找回入口超时或继续结算、调度队列。 |

同一流程可能同时产生前台和后台事件，不能按日志条数统计完成资源数。完成数量以任务记录和平台证据为准。

## 身份与错误详情

日志可记录运行、课程、资源、阶段、来源、事件码和序号。身份拒绝详情包括命令、规则、预期与实际课程身份、校验来源及路由类型；缺失身份用`null`并标记不完整。

`evidence`和`details`只接受有限的扁平白名单字段，包括已有的数量、目标、位置、时长、尝试次数及推进区间。字符串每字段最多240字符，数字必须有限；不接收任意嵌套对象。常见令牌和Bearer凭证会过滤，完整网址替换为`[url omitted]`。

## 导出与限制

在运行日志中选择“导出诊断”，可导出保留历史、故障、摘要和裁剪计数。导出只读，不触发播放、暂停、刷新或恢复。可选诊断保存失败会提示降级，不改变任务状态或恢复次数；关键任务状态保存仍按执行规则处理。

浏览器崩溃、保存窗口、容量裁剪或存储失败可能造成证据缺失。日志可以说明哪个命令因什么校验被拒绝，但不保证能解释页面身份为何变化或平台为何报错；证据不足时应记录“原因未确认”，不能直接归因服务器。
